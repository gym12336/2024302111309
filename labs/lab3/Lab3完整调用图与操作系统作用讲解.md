# Lab3 任务要求与对应代码讲解

依据：[实验3：三级页表与物理内存管理 V3.1](lab3-实验说明书-学生版-V3.1.docx)。本文按实验书的四个阶段讲解当前工程，只展开 Lab3 的任务；启动、中断、调度仅在说明内存管理接入点时涉及。

阅读主线是：**实验要求什么 → 为什么需要 → 哪些文件实现 → 每一步做什么 → 验收如何解释。**

## 一、实验究竟要改变什么

实验书描述的出发点是：Lab2 使用平坦地址空间，用户程序与内核缺少独立的内存映射，内核还可能直接使用用户传入的指针。

Lab3 要完成三项根本变化：

1. 把空闲 RAM 按 4KB 页统一管理，支持分配和回收。
2. 建立 Sv39 三级页表，让各进程拥有独立的虚拟地址空间和权限。
3. 让原有系统调用、程序装载、fork/exec 等功能适应分页，安全地访问用户内存。

**页表是操作系统交给 CPU 的地址对应表。** 程序使用虚拟地址，CPU 查对应页表后才知道访问哪块真实 RAM，以及此次访问是否允许。

例如：

```text
程序使用 VA 0x4000
    ↓ 查本进程页表
实际访问 PA 0x87ff2000
```

这里不是把数据搬到 0x4000，而是记录“访问这个虚拟地址时，去那块物理内存”。映射按页建立，所以同一映射还包含：

```text
VA 0x4008 → PA 0x87ff2008
VA 0x4fff → PA 0x87ff2fff
```

页内偏移保持不变。

| 操作 | 改变什么 | 不可混淆的含义 |
|---|---|---|
| `kalloc()` | 物理页的空闲状态 | 领取真实内存 |
| `mappages()` | 指定页表中的对应关系和权限 | 给虚拟地址安排去处 |
| 写 `satp` | CPU 当前采用的页表 | 开始按指定页表翻译地址 |

## 二、准备任务：增量包修复与 Sv39 基础

### 2.1 实验书第 0 节要求的两处修复

| 文件 | 本工程的处理 | 为什么必需 |
|---|---|---|
| [riscv.h](../../kernel/riscv.h) | 添加头文件保护 | 防止多处 include 后出现重复定义 |
| [trampoline.S](../../kernel/trampoline.S) | `trampsec` 使用 `"ax"` 属性并按 4KB 对齐 | 保证跳板代码被正确装入镜像，且可按整页映射 |

这两项是进入正式四阶段前的准备，不能把编译或链接错误误认为页表算法错误。`trampoline_link.S` 是编译跳板的包装入口，其 include 是构建期文本展开，不是运行时调用。

### 2.2 本实验用到的硬件规则

```text
VA：VPN[2] 9位 | VPN[1] 9位 | VPN[0] 9位 | 页内偏移 12位
              L2索引         L1索引         L0索引
```

一页 4096 字节，一张页表也占一页；每项 PTE 为 8 字节，所以每张表有 512 项。

- `V=1`：PTE 有效。
- 有效项的 `R/W/X` 全为 0：非叶项，指向下一级页表。
- `R/W/X` 表示读、写、执行权限；`U` 表示用户态可以访问。
- 本工程为普通内存建立 L0 的 4KB 叶映射，不实现大页遍历。
- `satp` 的 MODE=8 表示 Sv39，其 PPN 指定根页表物理页号。

[riscv.h](../../kernel/riscv.h) 提供 `PX`、`PA2PTE`、`PTE2PA`、`MAKE_SATP` 等支持。它们是已有基础接口，理解用途即可，不应都算作本次新写的实现。

## 三、阶段一：物理页分配器

### 3.1 实验要求

实现 `kinit/kalloc/kfree`，按 4KB 分配和回收；遵守学号派生的分配顺序及配额，准确统计空闲页。

核心问题是：**哪些 RAM 可以分给别人，哪些已经有人使用？**

### 3.2 文件分工

| 文件 | 职责 |
|---|---|
| [kalloc.c](../../kernel/kalloc.c) | 实现位图、初始化、分配、释放和计数 |
| [kalloc.h](../../kernel/kalloc.h) | 声明接口及 `kalloc_stats` |
| [memlayout.h](../../kernel/memlayout.h) | 提供 `KERNBASE/PHYSTOP` 等地址布局 |
| [course_sid.h](../../kernel/course_sid.h) | 提供个性化参数，不直接修改 |
| [kernel.ld](../../kernel/kernel.ld) | 导出内核镜像末尾 `kernel_end` |

### 3.3 kinit：划定可分配范围，建立账本

本工程 RAM 为 `[0x80000000, 0x88000000)`。前面已经放了内核及内嵌镜像，不能重新分配。

你的参数是：

```c
LAB3_ALLOC_ORDER = 1     // 降序分配
LAB3_MEMCAP_DELTA = 13   // 顶部排除 13 页
LAB3_GUARD_PAGES = 2     // 阶段四使用
```

`kinit()` 计算：

```text
first = PGROUNDUP(kernel_end)
limit = PHYSTOP - 13 × 4096 = 0x87ff3000
可分配范围：[first, limit)
最高可分配页首：0x87ff2000
```

随后将范围内各页对应的位设为 1，并记录总页数、空闲页数和最高候选位图字。范围之外的位保持 0。重复初始化被拒绝，避免把已经分配的页重新记为空闲。

**kinit 只是登记内存，不为每个空闲页再分配一份内存。**

### 3.4 为什么选位图

每页使用一位：1 为空闲，0 为不可用或已分配。128MB RAM 共 32768 页，位图只需 4096 字节。

实验书要求讨论链表与位图的取舍。若有序链表释放时逐个寻找插入位置，大量释放可能累计为 O(n²)。本工程位图释放的元数据更新是 O(1)，另有固定 4096 字节填充；分配需要查找候选字及位，并非所有情况都严格 O(1)。

### 3.5 kalloc：领取并清零一页

```text
检查初始化状态及空闲数量
 → 从最高候选字向下找非零位图字
 → 选该字最高空闲位
 → 清除该位、空闲数减一
 → 算出 PA
 → 将整页清零
 → 返回页首
```

页号与地址换算：

```text
page_index = (PA - KERNBASE) / 4096
word = page_index / 64
bit = page_index % 64
```

清零防止旧使用者数据泄露。页表页尤其需要清零，否则垃圾值可能被当成有效 PTE。

耗尽时返回空指针，调用者必须检查。页表、用户数据、frame 和内核栈使用同一分配器，都计入配额。

### 3.6 kfree：验证后归还

```text
检查初始化、4KB 对齐、范围
 → 检查该页是否已经空闲，拒绝重复释放
 → 整页填 0xA5
 → 位图设 1、空闲数加一
 → 必要时上移最高候选字
```

填垃圾数据帮助暴露释放后仍使用旧指针的问题；重新分配时仍会清零。当前分配器适用于实验单核调用方式，没有多核锁。

### 3.7 阶段一验收要点

能解释托管范围、降序选择、配额、清零、填垃圾和计数守恒。验证内容包括页对齐、释放后数量恢复、重分配清零、耗尽返回空、拒绝重复释放。实验书建议临时测试逻辑隔离在正式构建之外。

## 四、阶段二：页表遍历、映射、拆除与回滚

### 4.1 实验要求与文件

核心是建立地址对应关系，并保证**中途失败后恢复到申请之前的状态**。

[vm.c](../../kernel/vm.c) 实现 `walk/mappages/uvmunmap/vmfree` 及辅助 `prune`；[vm_ops.h](../../kernel/vm_ops.h) 提供接口；`riscv.h` 提供地址和 PTE 操作宏；`kalloc.c` 提供页表页。

### 4.2 walk：找到需要修改的页表项

```text
根表 L2
 → 用 PX(2, va) 找项
 → 到 L1，用 PX(1, va) 找项
 → 到 L0
 → 返回 &L0[PX(0, va)]
```

`walk` 返回 **PTE 的地址**，因为调用者要读取或改写这项，而不只是读取载荷内容。

- 中间表存在：从 PTE 解出下级表 PA，继续。
- 中间表不存在且 `alloc=0`：返回失败。
- 中间表不存在且 `alloc=1`：`kalloc()` 分配清零页，写入仅含 V 的非叶项。
- 在中间层遇到叶映射：当前实现不处理，返回失败。

每张下级表也是物理页，因此建立映射会产生页表内存开销。

**CPU 日常访存自己查页表；不会每次执行 C 的 walk。**

### 4.3 mappages：填写 VA→PA 和权限

假设给 VA `0x4000` 映射一页，载荷 PA 为 P，权限为 R/W/U：

```text
检查地址对齐、范围和权限组合
 → walk(root, 0x4000, 1)
 → 确认原 PTE 没有有效映射
 → 写入 PA2PTE(P) | R | W | U | V 等标志
 → 刷新翻译
```

其效果是让该页的虚拟地址访问落到 P 所在物理页，并允许用户读写、不允许执行。当前实现也预置 A/D 状态位。

遇到已有有效映射时返回错误，不覆盖旧映射，避免意外丢失原资源的归属。

### 4.4 本实验核心：失败回滚和资源归属

有两种资源必须分别考虑：

- **表页**：保存 PTE，由 walk 按需申请。
- **载荷页**：保存用户内容，由 add_page 等调用者申请后交给 mappages。

| 函数 | 负责回滚什么 |
|---|---|
| `walk` | 本次遍历新建但未能完成的中间表，逆序清链接并释放 |
| `mappages` | 本次已完成的前若干页映射，撤销时不释放调用者传入的载荷 |
| `uvmunmap/prune` | 清叶项、按参数归还载荷，并裁剪空的下级表 |
| `add_page` | 自己领取但映射失败的载荷页 |
| `proc_sbrk` | 本次扩展中前面已成功增加的所有用户页 |

例如 walk 新建 L1 后，申请 L0 失败，必须撤销新 L1，不能把它留在根表。若大区间映射前 N−1 页成功、第 N 页失败，则撤销本次前 N−1 页，而不是把其他既有映射一起删除。

**mappages 不拥有调用者传入的载荷，所以回滚不能随意 kfree 那些 PA。**

### 4.5 uvmunmap：去掉地址关系，可选归还物理页

`release=0` 表示只撤销映射；`release=1` 表示也归还对应载荷。

```text
walk 找叶项
 → 保存 PA
 → 将 PTE 清零
 → sfence.vma
 → 若 release=1，kfree(PA)
 → prune 清理已经空掉的下级表
```

必须先取消映射、刷新，再释放页。否则该页重新分给其他进程后，旧映射仍可能访问它，破坏隔离。

`prune` 只有确认整张下级表没有有效项时才释放，避免损坏仍在使用的其他映射。

### 4.6 vmfree：销毁整套动态用户页表

递归释放下级表和根表；`payload=1` 时还释放带 U 的叶子载荷。跳板和 frame 没有 U，不按普通用户载荷处理。frame 由进程清理函数另行释放，共享跳板不能随单个进程释放。

这是当前进程资源归属约定下的用户表销毁方法，不是任意内核映射的通用释放器。

### 4.7 阶段二验收要点

能画出三级表、说明 PTE 指针与 PA 的区别、解释重复映射为何报错，以及失败时每层释放谁。实验书要求在受限空闲页情况下触发中途失败，检查原有映射保留、临时表清理及计数恢复；不直接改只读配额宏。

## 五、阶段三：构建内核页表并开启分页

### 5.1 实验要求与文件

要求分页开启后内核仍能访问代码、全部 RAM、UART、PLIC，并为后续用户切换准备同址跳板。

[boot_vm.c](../../kernel/boot_vm.c) 的 `boot_vm_init()` 是本工程对应初始化函数；它调用阶段一 `kinit` 和阶段二 `mappages`。`main.c` 只负责调用，不需要在这里展开整个启动流程。

### 5.2 映射清单及取舍

| 区域 | 当前做法 | 原因 |
|---|---|---|
| UART | 恒等映射，RW | 驱动直接读写设备寄存器 |
| PLIC | 恒等映射，RW | 驱动直接操作中断控制器 |
| RAM：KERNBASE 到 PHYSTOP | 恒等映射，RWX | 内核要访问镜像及所有动态分配页 |
| CLINT | 未建立直接 MMIO 映射 | 当前时钟通过 time/stimecmp CSR 访问 |
| TRAMPOLINE | 高 VA→跳板 PA，RX，无 U | 跨页表切换时保持取指连续 |
| TRAPFRAME | 高 VA→当前 frame PA，RW，无 U | 通过固定别名访问现场 |
| 私有内核栈 | 动态分配，通过 RAM 恒等映射访问 | 当前未使用 KSTACK 宏建立独立高地址栈映射 |

实验书允许自行决定是否采用 KSTACK 高地址映射，但要求设计笔记和 Lab0 图纸说明一致。因此不能仅因为头文件有 KSTACK 宏，就认为当前代码已实现其高地址栈及 guard 布局。

内核 RAM 统一 RWX 是实验书允许的阶段性约束：预置链接脚本未提供 etext，当前没有细分内核代码与数据权限。用户代码仍必须禁止写入。

为什么要映射到 PHYSTOP，不能只到 kernel_end？因为 kalloc 领取的新页在镜像之外，内核清零新页、写 PTE、复制用户内容都要访问它们。顶部 13 页不参与分配，不影响内核恒等映射仍覆盖到 PHYSTOP。

### 5.3 satp 和刷新

```text
MAKE_SATP(root) = Sv39 模式字段 | 根表物理页号
根表物理页号 = 根表 PA >> 12
```

代码先建完整映射，再执行刷新、写 satp、再次刷新。TLB 缓存旧的翻译结果，不刷新可能继续使用已过时的 PA 或权限。

内核 RAM 恒等映射保证开启分页前后，当前代码和栈仍然落到正确物理位置。root/top_l1/top_l0 是静态表，其他所需下级表由 mappages 动态申请。

`sfence.vma` 只作用于当前核心；本实验单核，多核要另行通知其他核心处理旧翻译。

### 5.4 阶段三验收要点

启用分页后正常输出并能交互。要能解释每个必需映射、CLINT 取舍、栈映射方案、satp 构成和刷新时机。只看到“串口还能打印”不足以证明全部用户映射正确。

## 六、阶段四：独立用户空间及原有功能的页表化改造

这是前面三个阶段真正服务用户程序的地方。实验书的每项要求分别对应以下任务。

### 6.1 用户页表：各区域及权限

主要文件：[proc.c](../../kernel/proc.c)、[proc.h](../../kernel/proc.h)，依赖 vm.c、kalloc.c、memlayout.h。

本工程布局：

```text
低 VA
代码/只读区       r-xu
数据/BSS          rw-u
guard × 2         不映射
用户栈 × 2 页     rw-u
------------------------- 初始 sp、sz、heap_base
后续 sbrk 的堆    rw-u
……
TRAPFRAME         rw--
TRAMPOLINE        r-x-
高 VA
```

权限四位依次为 R/W/X/U，横线表示该权限未设置。

代码不可写，防止用户修改指令；数据、栈和堆可读写；特殊页没有 U，用户态不能直接访问。它们放在用户表中，是供进入 S 模式后、尚未切内核表的跳板代码使用。

### 6.2 为什么代码与数据必须按页分开

实验书强调 flat binary 没有完整的 ELF 段权限信息；若代码与数据落在同一页，要允许数据写入就会连代码也允许写入。

本工程构建链：

```text
Makefile 生成派生 user-lab3.ld，让 data_start 按页对齐
 → tools/link_user.py 使用派生脚本链接 VA=0 的用户 ELF
 → 生成 flat bin
 → tools/gen_user_meta.py 提取 entry/end/data_start
 → kernel/user_meta.h 的 image_metadata
 → proc.c:load_image 按 meta->data 分配 RX 或 RW 权限
```

`kernel/userimg.S` 嵌入程序字节。当前通过独立元数据数组配合内嵌镜像表传递边界，不应误解为 flat bin 自己包含权限。

用户程序恢复按基址 0 链接，并装载到用户 VA 0；不再依靠 Lab2 的固定物理基地址方案。VA 0 现在可以映射到任意合法载荷 PA。

### 6.3 创建、装载与 PCB 生命周期

`allocate_process()` 为进程领取私有 frame、私有内核栈，并通过 `new_table()` 建立含特殊映射的基础表。

`load_image()` 再建候选表，对普通用户页逐页调用：

```text
add_page → kalloc 领取载荷 → mappages 建立用户映射
```

随后通过 PTE 得到 PA，把内嵌镜像复制进去。所有映射成功后才替换 p->pagetable，设置入口 epc、栈顶 sp 和边界字段，再销毁旧表。guard 区间直接跳过，不申请载荷。

| PCB 字段 | 内存管理用途 |
|---|---|
| pagetable | 该进程根表 |
| sz | 当前用户空间上边界 |
| heap_base | 堆允许收缩的最低边界 |
| guard | 保护区起点 |
| image_size | 镜像内存大小 |
| frame | 私有用户寄存器现场 |
| kernel_stack | 私有内核栈顶 |

创建时分配，运行时选中其表和现场，exec 时替换用户空间，销毁时归还资源。这就是实验书要求解释的页表生命周期。

### 6.4 跳板与 stvec：只解释 Lab3 必须改的连接点

用户表不映射普通内核 C 代码，因此不能在 C 中切成用户 satp 后继续顺序执行。必须先跳到两张表同 VA、同 PA 的 TRAMPOLINE：

```text
trap.c:usertrapret
 → 高 VA 调用 trampoline.S:userret
 → 切用户 satp、刷新
 → 恢复现场
 → sret 进入 U 模式
```

反向进入内核：

```text
用户 ecall/中断/故障
 → 硬件进入 S 模式，但仍使用用户表
 → uservec 保存现场、切内核表
 → trap.c:usertrap
```

实验书特别要求：预置 uservec 不重置 stvec，所以 `usertrap` 第一行必须切为内核异常入口；返回用户前再设置为 uservec，防止内核异常误走用户保存路径。

`run_process()` 还通过 `boot_trapframe_select()` 让内核固定 TRAPFRAME 别名指向当前进程 frame，使内核表和该用户表的别名对应同一现场页。

这些是 Lab3 的分页接入要求，不需要据此重新学习整套启动或调度算法。

### 6.5 copyin/copyout：替换直接使用用户指针

主要文件：[user_mem.c](../../kernel/user_mem.c) 及头文件；调用点在 syscall.c、console.c、proc.c。

用户传给 write 的地址属于用户表，而内核执行时使用内核表，所以不能直接把该数值当内核指针。

当前实现：

```text
检查整个区间不越界、不溢出
 → 逐页查用户表
 → 验证 V、U、R，写入还要求 W
 → 得到载荷 PA
 → 通过内核 RAM 恒等映射复制
```

每次复制长度取：

```text
min(剩余长度, 4096 - 当前页内偏移)
```

因此用户 VA 连续而背后的物理页不连续时也能正确搬运。例如从 VA 0x4ffc 复制 8 字节，先从该物理页尾复制 4 字节，再查下一 VA 页对应的 PA，复制余下 4 字节。

当前选择“先完整校验，再分块逐字节搬运”。这会重复一些查表工作，但能避免发现非法后半段前已经写入目标前半段。实现检查范围、权限和物理页合法性，不等同于普通 memcpy。

| 旧调用点类别 | 当前路径 |
|---|---|
| write 用户缓冲区 | sys_write → user_readable/user_copyin → 64 字节内核缓冲区 → 输出 |
| read 用户目标 | console_read → user_writable/user_copyout |
| exec 用户名字 | proc_exec → user_copyin |
| wait 状态指针 | proc_wait/proc_exit → user_copyout |

内核装载器内部在已知合法 PA 之间 copy，不属于直接信任任意用户指针。

### 6.6 sbrk：按 EAGER 方式扩展和收缩

实验要求 SYS_sbrk 调用号为 12。本工程 dispatcher 转入 `proc_sbrk()`。

- `n>0`：从 PGROUNDUP(old) 起，为新涉及的每页立即分配载荷并建立 RWU 映射。全部成功才更新 sz，返回 old。
- `n<0`：不能低于 heap_base；拆掉缩小后不再需要的整页并归还物理内存，更新 sz，返回 old。
- `n=0`：返回当前边界。

这是 EAGER；不只是改 sz。LAZY 的缺页按需分配不在当前实验实现范围内。

OOM 时沿 kalloc → walk/mappages → add_page → proc_sbrk 逐层传递失败，撤销本次新增加的页和临时表，保持原 sz，最终向用户返回 -1。不能因配额耗尽而 panic。

sz 按字节记录，但分配按页进行；仍需保留的末页不会因少缩几个字节就被释放。

### 6.7 fork：逐页深拷贝，跳过 guard

`proc_fork()` 创建子进程资源，遍历父普通用户区域：

```text
有效页 → 给子分配新载荷、建立同 VA 映射、复制整页
无映射 guard → 跳过
```

```text
父 VA 0x4000 → PA A
子 VA 0x4000 → PA B
```

A/B 内容初始相同，但物理页独立，修改不会互相覆盖。当前没有实现 COW。

frame 由 allocate_process 私有分配，再复制寄存器现场；跳板共用同一只读可执行物理代码页，不按普通用户数据重复分配。复制失败时清理候选子进程，不能留下半个子空间。

### 6.8 exec：新空间成功才销毁旧空间

`proc_exec()` 安全读程序名，调用 load_image：

```text
旧空间保留
 → 建候选表、装载新程序
 → 任一步失败：释放候选，继续使用旧空间
 → 全成功：提交候选，释放旧用户页和旧表
```

这是实验书要求的失败原子性。PID 不变，但用户入口、代码、数据和栈被替换。当前实现仅使用程序名，不应据此推断它已支持通用 argv 装载。

### 6.9 guard 异常与退出回收

guard 不分配实际载荷，也不建立有效映射。用户访问时触发页异常；读取通常 scause=13，写入通常为 15。写不可写代码页同样会触发写页异常。

```text
uservec → usertrap 故障分支 → 打印 pid/scause/stval → proc_exit(-1)
```

当前处理会终止故障进程，不实现为这类缺页自动补页，也不专门把所有故障诊断为栈溢出。

回收：`release_process → vmfree(表,1) → kfree(frame) → kfree(内核栈) → 清 PCB`。必须避免释放当前仍在使用的内核栈；父正在等待时先切父进程，再在其下次陷入时通过 deferred 路径回收。子先退出的情况可由父后续 wait 回收。

### 6.10 dump_pagetable：按 ABI 观察，不是随意打印

[vm.c](../../kernel/vm.c) 的 dump_pagetable/dump_level 递归遍历有效项，[vm_printf.c](../../kernel/vm_printf.c) 负责格式化。格式依据 [dump_pagetable-ABI.md](../../gifts/dump_pagetable-ABI.md)：

```text
DUMP-PAGETABLE begin
L2 va=0x... pa=0x... perm=----
L1 va=0x... pa=0x... perm=----
LEAF va=0x... pa=0x... perm=r-xu
DUMP-PAGETABLE end
```

示例地址仅用于展示格式，实际输出为十六进制数。非叶 pa 指向下级表，叶 pa 指向载荷；perm 固定 R/W/X/U 四位，不输出 A/D。

现场应指出代码 r-xu、数据 rw-u、跳板 r-x-、frame rw--，并说明 guard 为什么没有有效叶项。输出必须与 Lab0 图纸对照，不能只说“打印成功”。

## 八、验收思考题的理解入口

1. **TLB 未命中要几次访问？** 对本实验三级 4KB 页映射，忽略页表遍历缓存等优化，一次翻译最多读取三级 PTE 共 3 次；再加真正的数据访问共 4 次。TLB 和页表遍历缓存等硬件机制减少开销。
2. **为什么先撤 PTE 再释放页？** 防止已重新分配的页仍被旧映射访问；当前实现还要在释放前使旧翻译失效。
3. **copyin 与 memcpy 差别？** copyin 理解用户页表并检查用户权限、范围和跨页关系，memcpy 只按当前地址空间读写指针，不能替代用户地址验证。
