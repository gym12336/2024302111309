# Lab4 自测用例

适用学号 `2024302111309`，策略 **ID9 两级优先级与8 tick老化**。同一个内核支持单核和双核；第一至三节策略边界固定在单核检查，第八节检查双核并发。测试通过标准事先按行为定义，不要求不同机器输出相同数值。

## 一、策略用例一　高低优先级的CPU边界

实现：[priority_test.c](../../user/priority_test.c)第一组孩子。父进程为高级观察者，孩子分别设置高/低基本优先级，短暂pause后运行纯计算负载。父进程取基线，再pause64 tick后取终点，比较cpu_ticks增量。

预期输出 `RESULT priority_cpu = high:low`，判据为总量大于32、low大于0、high大于2×low。high明显占优验证优先级，low非0验证老化下没有长期饥饿。这里验证行为边界，不宣称理论份额恒为某个固定比值。

## 二、策略用例二　耗尽时间片后等待老化再恢复

同一程序第二组中，高孩子持续计算；另一孩子在首次运行时自行设为低级，记录uptime和cpu_ticks，循环计算及采样，直到自身累计两个用户CPU tick。

第二个用户时钟会先触发yield，低孩子只有经过就绪等待老化后才能恢复并读到这两个CPU tick。它经退出码报告的耗时应为10～18 tick，而且必须先于高孩子完成。

当前版本单核复验输出 `RESULT aging_two_cpu_ticks_elapsed = 11 ticks`，包含两个CPU tick、至少8个READY等待tick和调度/采样边界，并非直接读取老化计数。应结合 `proc_clock()`的8 tick条件解释。轮转会过早恢复，无老化会拖到高孩子结束，均与此判据不同。

## 三、补充策略用例　同级轮转

第三组孩子均为高级，计算48 tick左右后取样，输出 `RESULT equal_priority_cpu = a:b`。两者均需大于8，且较大者不超过较小者两倍。此用例针对选择阶段每次从低槽扫描而导致同级饥饿的错误。

## 八、双核并发与同一镜像兼容

```bash
make qemu CPUS=1
make qemu CPUS=2
python3 tools/run_lab4_smp_checks.py
```

双核脚本默认启动三次独立QEMU，每次明确传入-smp 2。每次核对启动横幅只有一次、shell正常、smptest及后续程序通过，最后逐条检查shell恢复。脚本源码见[run_lab4_smp_checks.py](../../tools/run_lab4_smp_checks.py)，结果见[smp-checks.txt](evidence/smp-checks.txt)、[完整串口](evidence/smp-runtime-serial.txt)。

| 检查 | 事先定义的判据 | 可排除的问题 |
|---|---|---|
| 确实双核运行 | online_mask=3，hart0/1的dispatches和user_ticks增量均大于0 | 仅传CPUS变量、仅分配cpu数组、副核上线却不运行用户程序 |
| 共享进程表与生命周期 | 每轮8工作进程，嵌套fork、失败exec保留旧镜像、成功exec hi、按pid回收全部负退出码 | 同一进程被两核重复选中、错误唤醒、子进程和退出码遗失 |
| 页分配与地址空间 | 父子/孙子写不同字节；并发sbrk增长与收缩；三轮前后free_pages相等，最终退还父进程堆页 | 重复分配同一物理页、数据串扰、页表或进程资源泄漏 |
| 阻塞和kill | pause期限满足；kill睡眠孩子后wait得到-1且及时结束 | 丢失唤醒、被kill后仍永久休眠 |
| 全局时间 | 硬件time增量与uptime增量之比在每tick 80000～120000计数范围 | 两核都递增全局ticks导致计时翻倍 |
| 历史行为 | 三次启动覆盖bench、alt、schedcheck、proctest、vmtest、memcap、badaccess、pagedump、hi | SMP修改破坏已有陷入、内存、OOM与交互路径 |

smptest的hart计数按物理核统计，允许进程迁移，不要求某个孩子固定在某核。计数和内存快照并非全机同时冻结的事务；空闲页比较安排在本轮全部孩子被wait回收后，因此静止点的资源守恒才有明确含义。串口按字节保护，多个孩子的hi行可能交错；测试以父进程回收后的结果行判断。

|---|---:|---:|---:|---:|
| 1 | 164 / 106 | 131 / 99 | 123 / 13660056 | 32607 |
| 2 | 118 / 102 | 176 / 99 | 125 / 13828550 | 32607 |

三次的online_mask均为3；每次内部三轮并发回收后空闲页均为32601，最终退还父进程6页堆空间后为32607。每核计数和具体耗时允许变化，判据是两核实际有用户采样、所有工作完成、资源归还以及计时速率正确。
