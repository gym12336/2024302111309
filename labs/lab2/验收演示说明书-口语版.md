## 3. 整个实验流程怎样介绍

### 3.1 一分钟总述，可以直接练这一段

> 我按说明书的四个阶段完成。第一阶段先打通用户态进入内核、处理后再返回的通道；第二阶段让内核根据调用编号提供获取进程编号、输出和退出等服务；第三阶段接入串口中断，用64字节环形缓冲区暂存输入，再交给读取函数；第四阶段装载命令行程序，把前面几个部分联调起来。
>
> 所以整个实验有两个主要方向：一个是程序主动向内核请求服务，另一个是设备通过中断通知内核有输入。最终我在命令行输入一个程序名，内核就能运行对应程序，程序退出后命令行继续工作。

### 3.2 开机后，命令行程序是怎么跑起来的

```text
处理器启动 → 内核完成基本设置并打印启动文字
→ 从内嵌程序表找到命令行程序
→ 把程序内容放到内核末尾之后的内存
→ 准备页表、用户栈和首次寄存器现场
→ 设置程序入口和栈顶
→ 通过返回指令进入用户态
→ 用户程序打印提示符并等待输入
```

**现场讲法：**

> 这轮还没有文件系统，用户程序是在构建时直接放进内核镜像的。我按名字从程序表里找到命令行程序，再复制到它自己的运行内存。加载位置从内核结束地址之后开始，避免盖掉内核。然后给它准备栈和寄存器现场，就能通过已有的返回通道开始运行。

“首次现场”指内核主动准备的初始寄存器值，不需要这个程序先运行过。入口决定从哪条指令开始，栈顶决定函数调用时使用哪块内存。

### 3.3 一次输出请求：用户程序怎样借内核打印

以write(1, "hi", 2)为例，即向标准输出打印两个字节。

```text
用户程序准备调用编号和参数
→ 执行ecall，请求进入内核
→ 跳板保存用户寄存器，换到内核栈和页表
→ 内核根据调用编号选择输出服务
→ 检查用户缓冲区，取出内容并发送到串口
→ 把结果写入用户现场，准备继续执行的位置
→ 跳板恢复用户页表和寄存器
→ 执行sret，用户程序继续
```

**现场讲法：**

> 用户程序先把“要做什么”和参数放进寄存器，再执行系统调用指令。处理器把控制权交给内核入口，但寄存器还没有保存，所以跳板先把现场存好，并换成内核自己的栈和页表。内核检查请求和用户地址，输出内容后把结果写回现场。最后恢复用户环境，回到请求指令后面继续执行。

如果老师问具体寄存器，再补充：调用号放a7，前三个参数放a0、a1、a2，返回值放a0。输出服务的调用号是16。

### 3.4 一次键盘输入：为什么没有调用请求也能进内核

```text
键盘字符到达模拟串口
→ 串口产生接收中断
→ 中断控制器把通知送到处理器
→ 处理器进入内核中断入口并保存被打断的现场
→ 内核从串口取走字符，存入环形缓冲区并回显
→ 处理完中断，返回被打断的位置
→ 读取函数把已发布字符复制到用户缓冲区
```

**现场讲法：**

> 键盘输入是设备主动通知内核，不需要用户程序先发一条系统调用。内核收到通知后取走字符，先放到缓冲区里。程序需要输入时，再通过读取服务取出来。这里缓冲区相当于临时存放点，解决输入到达和程序读取不在同一时刻的问题。

设备中断可能打断用户程序，也可能打断正在等待输入的内核读取函数。两条入口都保存各自的现场；处理完以后都应继续原来被打断的工作。

### 3.5 输入hi后，为什么命令行不会跟着一起退出

```text
命令行收集hi和回车
→ 创建一个子进程，父进程保留命令行内容
→ 父进程等待，子进程获得运行机会
→ 子进程把自己的程序替换为hi
→ hi获取编号、输出并退出
→ 内核把等待结果交给父进程并回收子进程位置
→ 父命令行继续显示提示符
```

**现场讲法：**

> 命令行先创建子进程，让子进程运行这条命令，父进程保留原来的命令行。子进程再把自己的程序换成hi，输出后退出。父进程等到它结束，就继续接受下一条命令。

代码里的fork就是“创建子进程”，exec是“替换当前进程的程序”，wait是“等待子进程结束”，exit是“退出当前进程”。口头讲中文含义即可，老师追问函数时再对应名字。

**本轮的具体实现**：先让父进程从创建调用返回，父进程执行等待时才运行子进程；子退出时准备父的用户返回结果，直接恢复父用户现场。还没有能在任意位置暂停、恢复内核工作的通用调度器。

## 4. PDF三道思考题：短回答与追问解释

先说每题的“短回答”；老师继续问时，再讲例子或代码对应。不要把整段备查解释一次全背出来。

### 4.1 第一题：ecall和sret各做什么？为什么硬件不自动保存寄存器和切栈？

**短回答：**

> ecall是用户程序请求内核服务的入口。在本实验的设置下，处理器进入内核权限，记下请求发生的位置和原因，再跳到指定入口。它不自动保存普通寄存器，也不替我们换栈和页表，所以这些由跳板完成。
>
> 返回前，软件先恢复用户寄存器和页表，再由sret按照准备好的权限和返回位置继续用户程序。硬件提供基本的进入和返回机制，把现场放在哪、用哪个栈留给操作系统决定，系统设计就更灵活。

**追问：为什么必须保存寄存器？**

> 用户程序和内核使用的是同一套寄存器，切换权限不会自动换一套。比如用户正把计算结果放在一个寄存器里，内核处理请求也要用它。如果不先保存，回来时原来的计算结果就没了。所以先保存，处理后再恢复；作为返回值的寄存器按约定改成新结果。

**追问：栈为什么要换？**

> 栈存函数调用的返回位置和局部变量。刚进入内核时，栈指针仍是用户提供的值，不能直接拿它当内核栈。跳板先保存用户栈指针，再换成这个进程自己的内核栈，返回时恢复用户栈。

**追问：为什么跳板用汇编？**

> 刚进来时寄存器还没保存，栈也还是用户栈。普通C函数可能一开始就用栈、改寄存器，所以这部分要用汇编精确安排保存和切换顺序，准备好以后再进入C函数。

**追问：保存在哪里？**

> 每个进程都有一块现场内存，保存普通寄存器，还提前存好下一次进入内核所需的页表、栈顶和入口。C结构体的字段顺序必须和赠送汇编的偏移一致，不然就会读错位置。

备查：现场结构体名为trapframe，36个八字节字段，共288字节；其中31项为可变化的整数寄存器，其余5项保存进入内核所需信息。还有一个整数寄存器恒为零，不需要保存。

### 4.2 第二题：系统调用为什么要推进sepc？时钟中断也这样做吗？

**短回答：**

> 系统调用发生后，sepc记的是调用指令本身的位置。这条指令长4字节，所以返回前要把继续执行的位置加4，跳过已经处理的调用。否则回去又执行同一条请求，可能反复打印或一直循环。
>
> 时钟中断是异步打断程序，没有一条请求指令需要跳过，所以保持原位置继续，不能照着加4。串口中断也是这个道理。

**具体例子：**

```text
系统调用指令在0x1000
处理器记录sepc=0x1000
软件准备的继续位置变成0x1004
返回后从0x1004继续
```

这是帮助解释的示例地址，不是要求背诵当前程序的实际调用地址。

**追问：代码到底改的是哪一个值？**

> 我先把处理器记录的位置保存到进程现场里。确认是用户系统调用时，把现场里的继续位置加4；返回准备时再写回处理器的返回地址寄存器。不是硬件自动跳过，也不是遇到任何陷入都加4。

**追问：这里已经实现时钟调度了吗？**

> 本轮没有实现时钟抢占。我这里真实处理的是串口外部中断，也验证了它保持返回位置。时钟中断不加4是按硬件返回语义回答，不能把它说成已经实现了时间片调度。

### 4.3 第三题：行缓冲和字符流有什么区别？只改一处会怎样？

**短回答：**

> 字符流是每收到一个字符就让它可读；行缓冲正常要等换行后才把一行交给读取者。中断处理要决定什么时候发布输入，读取函数也要按对应规则取数据，两边要配合。
>
> 我的字符流读取可以按当前已有数量返回，不必等到凑满请求长度。行缓冲读取遇到换行就结束，把下一行留给下一次读取。如果只改中断的发布条件，不改读取逻辑，行缓冲就可能一次取走两行；如果只改读取而仍等换行才发布，字符流又不能及时读到单个字符。

**具体例子：假设两行已经全部进入队列。**

```text
输入：AB回车CD回车，共6字节
请求：最多读取64字节

字符流：一次可返回6字节
行缓冲：第一次返回3字节，第二次返回3字节
```

回车对应的换行字节也计入长度。字符流在数据分批到达时可能先返回更少字节，上面“一次6字节”的前提是六个字节都已经可读。

**追问：你为什么输入hi仍要回车？**

> 字符已经可以逐个读到，但用户态命令行程序还在拼完整命令，遇到回车才结束收集。内核的读取语义和命令行的命令执行规则不一样。

**追问：行模式遇到超过64字节、一直没有换行怎么办？**

> 我增加了满容量时发布片段的例外，让读取者先释放空间。否则一边等换行，一边队列满了又存不进新字符，可能一直无法继续。这个例外和满时丢新字符的策略都写进设计笔记，并且做了测试。

## 5. 老师可能追问的设计问题

### 5.1 系统调用和中断有什么区别？

> 系统调用是程序主动请求服务，比如请求打印；中断是设备主动通知处理器，比如键盘输入到了。两者都要进内核，但发起者和返回位置处理不同：调用处理后跳过请求指令，中断处理后继续被打断的工作。

### 5.2 输入缓冲区为什么要做成环形？

> 数组长度固定是64，写到末尾后可以回到开头，复用已经读走的位置。我用不断增长的计数记录读写进度，访问数组时对64取余，满不满看计数差值，不只看数组下标是不是相同。

> 比如读计数是62，新输入第64、65个字节会用到数组末尾和开头。只要旧数据已经被读走，就可以复用，不需要把整个数组里的内容搬动。

备查：r表示读到哪里，e表示已经存到哪里，w表示允许读到哪里；满时看e-r是否达到64，可读为空时看r是否等于w。字符流每次接受后令w=e，行模式按发布规则更新w。

### 5.3 缓冲区满了为什么丢新字符？会覆盖旧内容吗？

> 这是本轮选择的简单策略：满了丢新字符，记录丢弃数量，不覆盖排队的旧内容。即使丢弃，也要把硬件里的字节取走并完成中断处理，避免设备一直反复通知。

> 例如队列里已经有64个未读字符，又到一个新字符，我就丢弃这个新字符并增加计数。等旧字符被读走，空出来的位置又能接收新输入。丢弃的字节不回显。

### 5.4 没输入时程序怎么等？是不是已经“睡眠唤醒”了？

> 现在没有真正的进程睡眠队列。读取函数在内核里循环检查，等待期间允许串口中断运行；字符到达后就继续取数据。缺点是占用处理器，后续有调度器以后应改成阻塞等待和唤醒。

> 不能整个等待过程都关着中断，否则串口处理不了新输入，读取就一直等不到数据。

### 5.5 加载程序怎么避免覆盖内核？地址0又是什么意思？

> 我从链接脚本提供的内核结束位置之后，向上对齐到页边界，再安排进程内存。程序看到的地址和真正放在内存里的地址通过页表对应，所以用户入口可以是0，实际指令却放在内核之后的物理内存里。

> 页表就是地址转换表，还负责限制读、写和执行权限。因此不是把程序写进物理地址0，也不是让用户直接访问整个内核内存。

当前镜像备查：内核末尾0x800171d8，进程内存从0x80018000开始；程序虚拟入口为0。数值随构建变化，代码根据符号计算，不写死这些数字。

### 5.6 用户栈为什么要对齐？“首次现场”怎么构造？

> 用户栈占两页，也就是8192字节，向低地址增长，初始栈顶按16字节对齐，符合函数调用约定。下面还有一页不建立映射，用来发现栈向下越界。

> 第一次启动还没有旧现场，我就把现场清零，再填程序入口和栈顶。返回通道按这份初始状态恢复寄存器，处理器就从用户程序入口开始执行。

精确容量为8 KiB，即8192字节；初始用户栈顶0x13000，栈区0x11000～0x12fff，下面0x10000所在的一页是保护页。口头讲清“向下增长、16字节对齐、保护页”即可。

### 5.7 创建子进程为什么有两个返回值？

> 父进程和子进程各有一份保存现场。父进程收到的是子进程编号，子进程收到的是零，用这个区别走不同代码分支。例如父编号1、子编号2，父的创建调用返回2，子返回0，但子自己的编号仍是2。

### 5.8 替换程序和创建进程有什么不同？

> 创建进程会产生一个新编号和独立用户内存。替换程序是在已有进程里换掉程序内容，编号不变。所以子进程创建出来时还是命令行的副本，替换成hi以后编号仍是同一个。

### 5.9 等待的返回值是不是子进程退出状态？

> 不是。等待返回的是结束的子进程编号，退出状态另写到父进程提供的变量里。比如编号7的子进程退出状态为负三，等待调用返回7，状态变量里存负三。

### 5.10 四个进程槽位是不是完整多任务调度？

> 不是。本轮预留四个进程位置，各有自己的用户内存、现场、页表和内核栈。执行机会通过父进程等待来交接，没有时间片轮流抢占。这样能够支撑课程提供的顺序命令，但通用调度还要后续完善。

本轮每槽26页，四槽共416 KiB；程序区最多64 KiB。可直接说“固定内存的简化进程方案”，不用背每张表的地址。

### 5.11 还没有做的功能有哪些？

> 本轮完成了说明书要求的最小链路。当前没有文件系统、命令参数解析、时间片抢占和通用进程睡眠。程序代码和可写数据在同一页，当前给了读写执行权限，后续应分开页面、收紧代码权限。

这段对应当前实现的真实取舍，不要把简化方案说成完整操作系统。

## 7. 保留这些名词就够了

| 名词 | 现场可以怎样解释 |
|---|---|
| 用户态、内核态 | 同一处理器的两种权限，用户程序通过规定入口请求内核服务 |
| 系统调用 | 用户程序向内核提出服务请求 |
| 中断 | 设备通知处理器有事情要处理，保存现场后处理，再继续原工作 |
| 寄存器 | 处理器内部临时保存数值的小空间 |
| 保存现场 | 把原程序的寄存器和继续位置保存下来，避免被处理过程覆盖 |
| 跳板 | 负责保存/恢复现场、切栈和切页表的那段入口汇编 |
| 页表 | 把程序使用的虚拟地址对应到物理内存，并规定访问权限 |
| 栈 | 保存函数调用和局部数据的内存区域，用户和内核各有自己的栈 |
| 环形缓冲区 | 固定数组循环复用，暂存还没有被程序读取的输入 |
| 进程 | 程序的一次运行，加上它的内存、编号和现场 |
| ecall | 请求进入内核处理的指令；这一题保留原名即可 |
| sret | 根据准备好的状态返回的指令；本实验用户返回时回到用户态 |
| sepc | 记录陷入时指令位置、返回时提供继续地址的寄存器 |

其他英文缩写放在备查里，只有老师点名时再说：串口设备对应UART，中断控制器对应PLIC，现场结构体对应trapframe。首次介绍后就用中文名称继续讲。

## 8. 最后30秒总结

> 这次实验把用户程序请求内核服务、设备输入中断、输入缓冲和用户程序装载接成了一条完整链路。我现场展示了hi、spin、课程非法调用和串口输入测试，也逐字节验证了实验1启动输出。当前采用说明书允许的简化等待与执行方案，设计取舍和真实结果都保存在文档里。

答辩前最后记住五句话：先保存现场再用寄存器；系统调用返回加4、中断不加；字符流立即可读但命令要回车；队列满丢新字符、读空后可复用；子进程退出以后父命令行继续。
