# 第 3 步逐行讲解：跳板和地址映射

这份讲解只针对第 3 步已经做完的代码。Lab2 的用户程序还没有启动，系统调用也没有实现。阅读顺序是：CPU 看到什么地址 → 为什么需要跳板 → 怎样把跳板放进内核 → 怎样建立页表 → 测试究竟证明了什么。

## 1. CPU 执行代码时需要地址

CPU 用 **PC（程序计数器）**保存下一条要执行的指令地址。代码和数据最终都在硬件内存中；它们在硬件内存中的位置叫**物理地址**。在 QEMU 的 `virt` 机器上，本项目内核所在的 RAM 从 `0x80000000` 开始。这里的十六进制前缀 `0x` 只是书写地址的方式，并不是另一种内存。

程序也可以使用**虚拟地址**。CPU 此时需要查一张地址换算表，才知道对应哪块物理内存。这张表叫**页表**。例如本步把虚拟地址 `0x3ffffff000` 指向物理地址 `0x80001000`：数字不同，实际访问的是同一页代码。一个物理页可以被多个虚拟地址指向，这叫**别名映射**。

地址的最小映射单位通常是**页**。本步细粒度页为 4 KiB，即 4096 字节；一个地址可分成“页号”和“页内偏移”。映射只替换页号，页内偏移保持不变。所以如果页首 `0x3ffffff000` 指向 `0x80001000`，那么虚拟地址 `0x3ffffff09c` 就指向物理地址 `0x8000109c`。

## 2. Lab2 为什么需要跳板

后续用户程序运行在 **U 态**（用户权限），内核运行在 **S 态**（监督权限）；启动时还经过权限更高的 **M 态**。这些是 CPU 的权限级别，不是三个独立程序。系统调用 `ecall` 发生时，CPU 将进入 S 态，但不会自动把全部普通寄存器保存好，也不会自动换成内核栈。保存寄存器、换栈、调用内核处理函数的汇编代码就是**跳板**（`trampoline.S`）。

将来用户程序和内核会使用不同的页表。跳板在换页表的那一刻仍要继续执行，因此两套页表都需要在同一个虚拟地址 `TRAMPOLINE` 找到同一页跳板代码。`TRAPFRAME` 是紧邻其下的一页虚拟地址，跳板把用户寄存器保存到那里的内存。`TRAPFRAME` 不等于寄存器本身；它是一块供汇编读写寄存器快照的 RAM。

```text
CPU 使用的虚拟地址                 页表换算             实际物理内存
TRAMPOLINE  0x3ffffff000   ──────────────────>   0x80001000 的跳板代码页
TRAPFRAME   0x3fffffe000   ──────────────────>   boot_trapframe 暂存页
```

这里还有一个重要区别：**代码放在哪里**与**CPU 用什么地址访问它**不是同一问题。链接器负责前者，页表负责后者；本步必须两边都处理。

## 3. 链接器怎样把赠送汇编放入内核

编译器先把源代码编成 `.o` **目标文件**。这时一些函数地址还未确定。**链接器**读取 `kernel/kernel.ld`，给代码段和数据段安排最终地址，产出 `kernel/kernel` 内核镜像。**段或节（section）**是目标文件中的一个内容分组，例如可执行代码和只读数据分开存放。

赠送的 `trampoline.S` 把代码放进 `trampsec`，但它写的是 `.section trampsec`，没有声明这一节应占用运行时内存、应可执行。原始链接检查曾显示 `uservec=0x0`、符号类型 `N`，这不是可在内核 RAM 中执行的入口。

我们不改课程赠送汇编。在自有文件 `kernel/trampoline_link.S` 中先写 `.section trampsec,"ax"`，再 `#include "trampoline.S"`。这里 `a` 的意思是 **alloc**，运行时要给这一节分配内存；`x` 的意思是 **execute**，这一节里有指令。随后 `kernel.ld` 先对齐到 4096 字节边界，再放 `trampsec`，并断言其长度不超过一页。

这使 `uservec` 和 `trampoline` 的物理地址都变成 `0x80001000`，`userret` 位于同页的 `0x8000109c`。页对齐是为了以后能把完整的一页代码映射到固定虚拟页 `TRAMPOLINE`。`uservec` 是“用户进入内核”的入口，`userret` 是“内核回用户”的入口；它们是跳板同一页中的两个位置。

## 4. `boot_vm.c` 每组操作在做什么

### 4.1 准备三张页表页和一张现场页

`root`、`top_l1`、`top_l0` 都各有 512 个 64 位条目，恰好占 4096 字节。`aligned(PGSIZE)` 保证起始地址为 4 KiB 的整数倍，这是 RISC-V 页表硬件的要求。`boot_trapframe` 也是对齐的一页，但它用于存放现场数据，不是页表。这是一页启动阶段临时现场空间，后续要改为每个进程自己的现场页。

**Sv39** 是此处使用的 RISC-V 虚拟地址格式。它把虚拟页号分成三级索引，每级 9 位，因此每张页表有 `2^9=512` 项。`PX(2, 地址)`、`PX(1, 地址)`、`PX(0, 地址)` 分别提取第三级、第二级、第一级要查的下标。`root` 是查找起点。

### 4.2 先保住 Lab1 原有地址

`root[PX(2, UART0)]` 把低地址设备区域映射到同数值的物理地址；`root[PX(2, KERNBASE)]` 把从 `0x80000000` 开始的内核区域也映射到同数值的物理地址。这叫**恒等映射**。它使开启页表后，既有内核代码、栈和 UART 串口仍能按原地址工作。串口是 Lab1 输出文字的设备，地址失效就可能黑屏。

这两项是第三级直接指向数据页的**大页条目**，一项覆盖 1 GiB。这比内核实际占用范围宽得多，只是 Lab2 启动阶段的过渡设计，后续进程页表需要更细的权限范围。

### 4.3 给两个高地址单独安排 4 KiB 映射

`root[PX(2, TRAMPOLINE)]` 指向 `top_l1`，`top_l1` 再指向 `top_l0`；最后 `top_l0` 的两项分别指向跳板物理页和 `boot_trapframe` 物理页。这不是把整片高地址都开放，而是只开放两个相邻的 4 KiB 页。

每项页表记录叫 **PTE（页表项）**。代码中的 `PTE_V` 表示条目有效，`PTE_R/W/X` 分别代表可读、可写、可执行。跳板页是可读可执行，现场页是可读可写。两页都没有 `PTE_U`，表示用户权限不能直接访问；但 CPU 因 `ecall` 进入 S 态后，跳板可以访问这些页。`PTE_A/D` 记录访问和写入状态，本步预先设置它们，避免因状态位缺失而阻碍简单映射实验。

### 4.4 正式启用并立即检查

`satp` 是保存页表根地址和页表模式的 CPU 控制寄存器。`MAKE_SATP(root)` 选择 Sv39 并放入 `root` 的物理页号；`w_satp(...)` 之后，S 态地址访问开始经过页表。`sfence.vma` 会清除 CPU 先前缓存的旧地址换算结果；这类缓存常叫 **TLB**。

开启后，代码通过虚拟地址 `TRAMPOLINE` 读取一条指令，和物理地址 `trampoline` 处的内容比较；又通过虚拟地址 `TRAPFRAME` 写入标记 `LAB2`，从物理地址 `boot_trapframe` 读回，并把标记清掉。若地址映射不成立，读写会出错或自检会停住，Lab1 Banner 也无法照常完整打印。

## 5. 这次验收能证明什么

`nm` 显示 `uservec=0x80001000` 且类型为 `T`，`readelf` 显示 `.trampsec` 有 `AX` 标志，证明链接器已把代码放进可执行位置。QEMU 启动后，高地址别名读写自检完成，Lab1 输出和原有 446 字节期望文件逐字节相同，异常日志为空，证明本次开页表没有破坏现有启动与串口输出。

这还不能证明一次 `ecall` 能正确往返：用户程序、每进程页表、完整 trapframe 布局、寄存器保存恢复和系统调用分发都要在后续步骤实现。`kernel/trap.c` 此时只有意外陷入时打印信息并停机的入口。下一步只处理 trapframe 与赠送汇编偏移对齐，届时再解释每个字段。
