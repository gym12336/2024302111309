# 第 3 步逐行讲解：跳板和地址映射

这份讲解只针对第 3 步已经做完的代码。Lab2 的用户程序还没有启动，系统调用也没有实现。阅读顺序是：CPU 看到什么地址 → 为什么需要跳板 → 怎样把跳板放进内核 → 怎样建立页表 → 测试究竟证明了什么。

## 1. CPU 执行代码时需要地址

CPU 用 **PC（程序计数器）**保存下一条要执行的指令地址。代码和数据最终都在硬件内存中；它们在硬件内存中的位置叫**物理地址**。在 QEMU 的 `virt` 机器上，本项目内核所在的 RAM 从 `0x80000000` 开始。这里的十六进制前缀 `0x` 只是书写地址的方式，并不是另一种内存。

程序也可以使用**虚拟地址**。CPU 此时需要查一张地址换算表，才知道对应哪块物理内存。这张表叫**页表**。例如本步把虚拟地址 `0x3ffffff000` 指向物理地址 `0x80001000`：数字不同，实际访问的是同一页代码。一个物理页可以被多个虚拟地址指向，这叫**别名映射**。

地址的最小映射单位通常是**页**。本步细粒度页为 4 KiB，即 4096 字节；一个地址可分成“页号”和“页内偏移”。映射只替换页号，页内偏移保持不变。所以如果页首 `0x3ffffff000` 指向 `0x80001000`，那么虚拟地址 `0x3ffffff09c` 就指向物理地址 `0x8000109c`。

## 2. Lab2 为什么需要跳板

后续用户程序运行在 **U 态**（用户权限），内核运行在 **S 态**（监督权限）；启动时还经过权限更高的 **M 态**。这些是 CPU 的权限级别，不是三个独立程序。系统调用 `ecall` 发生时，CPU 将进入 S 态，但不会自动把全部普通寄存器保存好，也不会自动换成内核栈。保存寄存器、换栈、调用内核处理函数的汇编代码就是**跳板**（`trampoline.S`）。

将来用户程序和内核会使用不同的页表。跳板在换页表的那一刻仍要继续执行，因此两套页表都需要在同一个虚拟地址 `TRAMPOLINE` 找到同一页跳板代码。`TRAPFRAME` 是紧邻其下的一页虚拟地址，跳板把用户寄存器保存到那里的内存。`TRAPFRAME` 不等于寄存器本身；它是一块供汇编读写寄存器快照的 RAM。

```text
CPU 使用的虚拟地址                 页表换算             实际物理内存
TRAMPOLINE  0x3ffffff000   ──────────────────>   0x80001000 的跳板代码页
TRAPFRAME   0x3fffffe000   ──────────────────>   boot_trapframe 暂存页
```

这里还有一个重要区别：**代码放在哪里**与**CPU 用什么地址访问它**不是同一问题。链接器负责前者，页表负责后者；本步必须两边都处理。

## 3. 链接器怎样把赠送汇编放入内核

这一段只解决一个问题：**跳板指令怎样成为内核镜像中真正可运行的代码？** 可以分成三步看：

```text
trampoline.S（人写的汇编源文件）
    ↓ 编译
trampoline_link.o（目标文件，尚未决定所有最终地址）
    ↓ 与其他目标文件链接
kernel/kernel（QEMU 装载的完整内核镜像）
```

目标文件 `.o` 像有许多分格的箱子：某格放代码，某格放数据。**section（节）**就是一个分格。赠送的 `trampoline.S` 用 `.section trampsec` 把跳板指令放进名叫 `trampsec` 的格子，但没有说明这个格子应在运行时分配内存、允许执行。原先的链接探针看到 `uservec=0x0`、类型 `N`；对本实验来说，这不是内核 RAM 中可执行的入口。

自有的 `trampoline_link.S` 先声明 `.section trampsec,"ax"`，再通过 `#include "trampoline.S"` 把赠送源码接进来。`a` 表示运行时给这一节分配内存，`x` 表示其中可以放要执行的指令。**赠送文件本身保持原样。**

接着由**链接器**读取 `kernel/kernel.ld` 决定“把这格放在哪”。脚本将其起点移到下一个 4096 字节整数倍，再安放 `trampsec`，并检查内容没有超过一页。因此两处标签的最终位置是：

```text
0x80001000  trampoline / uservec：用户进入内核的入口
     ……     保存寄存器等指令
0x8000109c  userret：内核返回用户的入口
```

**标签**是给指令位置起的名字。`userret` 距这页开头 `0x9c` 字节，所以它的地址是 `0x80001000 + 0x9c`；两处标签属于同一页。页首必须对齐，是为了下一步能把这一整页准确映射到固定虚拟地址 `TRAMPOLINE`。简记：`trampoline_link.S` 说明“这格是可执行代码”，`kernel.ld` 决定“这格放在 `0x80001000`”，页表随后负责“虚拟地址怎样找到它”。

## 4. `boot_vm.c` 每组操作在做什么

### 4.1 先准备“地址查询表”和“现场存放处”

假设 CPU 要访问虚拟地址 `TRAPFRAME`。它需要一张查询表回答：“这个虚拟地址对应 RAM 的哪一页？”`boot_vm.c` 中的 `root` 就是查询起点。Sv39 采用**三级页表**：若第一张表没有直接给出最终物理页，就按记录找到第二张表，再找到第三张表。`top_l1`、`top_l0` 是这条查询链上后两张表。

为什么每张表是 `uint64 表名[512]`？一个 `uint64` 是 8 字节，`512 × 8 = 4096` 字节，恰好一页。数组中的一格叫**页表项 PTE**。`aligned(PGSIZE)` 要求这一页的起点能被 4096 整除，以便 CPU 按硬件格式找到它。

`boot_trapframe` 虽然也是 4096 字节、同样对齐，却**不是查询表**。它是映射成功后真正用来存放寄存器现场的 RAM。当前只有一页启动暂存空间；以后每个进程需要自己的现场空间。

`PX(2, 地址)`、`PX(1, 地址)`、`PX(0, 地址)` 分别从虚拟地址取出三级查询所需的数组下标。可以把虚拟地址想成写着“三层目录编号＋页内位置”的纸条：前面几个编号指导逐级查表，页内位置告诉 CPU 到最终那一页的哪个字节。

### 4.2 为什么先给老地址做“原样换算”

开页表以前，Lab1 的内核代码位于 `0x80000000` 一带，UART 串口位于 `0x10000000` 一带。开启页表后，CPU 会把这些数值当成虚拟地址查表。如果表里没有它们，CPU 连下一条内核指令或串口寄存器都可能找不到，表现为无法继续运行或没有输出。

所以代码先加入两条大范围规则：

```text
虚拟地址 0x00000000～0x3fffffff → 数值相同的物理地址（包含 UART）
虚拟地址 0x80000000～0xbfffffff → 数值相同的物理地址（包含内核）
```

这叫**恒等映射**：输入什么地址，就换算成同数值的物理地址。`root[PX(2, UART0)]` 实际是 `root[0]`，`root[PX(2, KERNBASE)]` 实际是 `root[2]`。每条规则覆盖 1 GiB，叫**大页映射**。范围很宽，是为了先保证已有内核正常启动；后续为用户进程建立的页表需要更精细的范围和权限。

### 4.3 两个高地址是怎样逐级找到物理页的

高地址需要精确到 4 KiB，不能用上一段覆盖 1 GiB 的粗规则。这里走完整的三级查询：

```text
root[255] → top_l1[511] → top_l0[511] → 0x80001000 跳板代码页
                            top_l0[510] → boot_trapframe 现场页
```

方括号里的数是数组下标，来自虚拟地址的不同部分。两条路线共享前两张表，最后才分开。于是 `TRAMPOLINE=0x3ffffff000` 找到跳板，紧邻的 `TRAPFRAME=0x3fffffe000` 找到现场页。

页表项 PTE 里除了“指向哪里”，还写着“允许做什么”。`PTE_V` 表示此项有效；`PTE_R` 是可读，`PTE_W` 是可写，`PTE_X` 是可执行。跳板页设为 **读＋执行**，因为 CPU 要读取并执行指令；现场页设为 **读＋写**，因为要保存和恢复寄存器。两页都没有 `PTE_U`，所以 U 态用户程序不能直接访问；跳板在 S 态可以访问。`PTE_A`、`PTE_D` 是访问和写入状态位，本步预先设置，避免它们影响这个最小映射实验。

### 4.4 表填好后，怎样告诉 CPU 开始使用

此前 `satp=0`，S 态按地址数值直接访问，没有启用 Sv39 换算。`satp` 是 CPU 的**页表控制寄存器**。代码执行 `w_satp(MAKE_SATP(root))`，就是告诉 CPU：“从现在起用 Sv39，从 `root` 开始查表。”因此 `root` 自己必须放在 CPU 能找到的物理内存中。

CPU 可能缓存旧的地址换算结果；这个缓存叫 **TLB**。`sfence.vma` 让旧结果失效，以便后续访问按新表查询。你可以先把它理解为“换新目录之后，清掉手里旧的地址便签”。

最后，代码**实际走一遍两条新路线**：通过 `TRAMPOLINE` 读取指令，与 `0x80001000` 的内容比对；通过 `TRAPFRAME` 写入 `LAB2` 标记，再从 `boot_trapframe` 读回。若两边指向同一物理页，值应一致。检查完成后清掉标记，避免它成为后续现场里的垃圾数据。

## 5. 这次验收能证明什么

验收分两层。第一层检查**内核文件里的摆放结果**：`nm` 是查看符号地址的工具，它显示 `uservec=0x80001000`，类型 `T` 表示代码符号；`readelf` 是查看内核文件结构的工具，它显示 `.trampsec` 具有 `AX` 属性。它们回答“链接器有没有把跳板放到合适的位置”，但不能单独证明 CPU 运行时能访问高地址。

第二层检查**QEMU 中的运行结果**：启动代码读写了两个高地址，并成功继续打印 Lab1 Banner。`cmp` 逐字节比较真实输出和期望文件，结果相同，两个文件均为 446 字节；异常日志为 0 字节。这说明这次开启页表后，两个新映射和原来的内核、UART 路径都能完成本次启动测试。

测试还没有让用户程序执行 `ecall`。因此它尚未验证“跳板保存所有寄存器 → 内核处理系统调用 → 跳板恢复寄存器”这条往返路。当前 `kernel/trap.c` 只有意外陷入时打印信息并停住的入口。后续会先把保存现场的 C 结构按赠送汇编的偏移定义好，再逐段接通往返。
