
学生须知 · 操作系统实践
写在前面：请在第 1 周开学时认真阅读本页纸。本课程采用"从零设计累积构建"的工程模式，规则透明、一视同仁。
一、这门课怎么拿分？
• 学期总评构成：现场验收占 70%（lab1 占 10%，lab2–7 各占 15%）；期末考查占 30%——由 第 14 周闭卷现场设计考查（满分 10 分，占总评 10%，三选一架构设计）与 第 15 周综合实验报告（满分 20 分，占总评 20%）两部分组成，两项得分直接相加（满分 30 分）计入期末考查成绩。
• 验收机制：每个实验你只有一次正式面对面"验收"——带着你从零逐步构建出来的操作系统，当着任课教师的面跑通核心功能、通过回归自检，并回答三个问题。
• 功能定上限，问答定档位：功能测试决定成绩上限，问答表现决定最终成绩档位。
• 单核基线定基准，双核进阶加分（+3分）：
◦ 单核为基准（A/B/C/D/E 均可定）：全学期所有实验（含 lab4–lab6）的基础验收基线统一为单核（-smp 1）。只要单核功能完整、状态流转正确、通过回归并答辩出色，完全可以评定为 A 档（95分）！单核绝不限制最高成绩。
◦ 双核为加分（自愿挑战，额外 +3分）：从 lab4 开始，系统支持自愿挑战双核并发（-smp 2）。若双核并发测试稳定通过，在当次实验基准得分上额外累加 +3 分（例如：单核评定 A 档 95分，双核通过则记为 98分；单核评定 B 档 85分，双核通过记为 88分，上限 100分）。
◦ 各次实验相互独立：挑战双核是每轮实验的独立选择。某轮未挑战双核或双核未通过，后续实验仍可继续选择挑战；某轮挑战了双核，后续实验即使只做单核基线，依然可以正常参评 A 档，绝不存在连带扣分或影响后续成绩的情况。
二、你拿到的是什么代码？
• 开学第 1 周：你将领取专属的初始基线包（包含 5 个空白文件、不可改动的系统引导与链接预置文件、以及按你学号派生的 15 项参数宏与派生公式）。全学期只有这一次个性化代码发放！
• 后续各轮实验：每两周发放一份全班统一的增量包（包含能力目标、接口约定、新的预置文件与支持代码、观测工具与测试集）。
• 没有任何"官方完整标准答案"会发给你：十五周后，这个内核的每一行代码、每个数据结构都是你亲自设计出来的。
• 关于开源参考：MIT 公开的 xv6 是合法的原理阅读参考（推荐对照学习），但课程实验拥有公开版没有的专属设计规范——包括定制系统调用号分配、用户程序内嵌加载机制、诊断输出规范，以及按你学号派生的 15 项参数宏。直接复制公开版代码无法通过课程测试，更无法通过针对个性化代码的现场问答。
三、每轮实验的标准工作流
0. 环境与调试就绪（仅第 1 次）：第 1 次课按《学生环境安装指引》装好工具链与 QEMU 并通过 preflight.py 自检（教师查截图）；通读《学生无gdb调试手册》——本课程不用 gdb，所介绍的核心调试方法是你全学期定位内核问题的关键手段。
1. 先做设计笔记（课前思考题）：思考题不单独判分、不收缴批改，但验收问答直接从思考题中抽选！动手前把数据结构、不变式与回滚路径想透彻。
2. 在自己的代码树上设计并实现：严禁修改包内的系统预置文件（预置文件规定了硬件与系统的接口边界）。
3. 给自己写两个测试用例：证明你的边界条件与错误路径处理正确。
注意分层：判定功能是否完成的官方测试随每轮增量包发放（support/tests/，验收现场运行）；你的自写测试先于实现写——它逼你在动手前想清楚规格与边界，且能覆盖只有你的参数才有的行为（官方测试主要检验全员一致的基础规范与正确性）。自写测试不批改，归档备查，验收问答会抽问。
4. 打标签与打包归档：
   git tag labN-submit
   git archive -o labN-<学号>.zip labN-submit

5. 按时参加现场验收：功能跑通 ＋ 通过早期实验回归命令 ＋ 三题问答。
四、Git 版本管理是必备工具（全学期只用四条命令）
1. git init：第一周领到基线后必须立即建仓并完成初始提交。
2. git tag labN-submit：每轮实验完成打标签锁定版本。
3. git archive：导出提交归档包，作为评测与备查证据。
4. git push（强烈推荐）：推送到个人的私有远程仓库备份。
📝 说明
代码修改出现异常时，用 git checkout 或标签回滚；跨实验出现的隐蔽回归，用 git bisect 二分定位。Commit 历史不单独打分，但当验收被问到"这段代码是你写的吗"时，清晰的提交记录是你最有力、最可信的证明。
五、AI 辅助编程政策
• 允许并鼓励使用 AI：全流程任何阶段均可使用 AI 工具辅助理解概念、编写代码或设计测试，无需提交对话记录。
• 但请时刻谨记：学生本人是系统设计的主导者，AI 仅是辅助工具。验收问答围绕你自己的个性化参数、你自己选择的数据结构、你自己写的失败回滚路径发问。背诵通用答案完全无用；解释不清因果关系，即使功能全通也无法通过验收。
六、代码质量与向后兼容：前期问题自主修复
• 全学期基于同一代码库持续累积演进，课程中途不重新发放完整初始代码。
• 后期实验会频繁用到前期实验构建的模块（例如 lab5 的写时复制会在 lab2 写的陷入分发中挂载缺页分支，lab6 的文件系统会替换前期的用户程序加载方式）。
• 每轮验收均包含一条早期实验的回归测试，前期遗留的缺陷会在后续暴露，必须自行定位并修复。教师只负责环境排查与思路启发，绝不替你代修代码。
七、热身实验与补验政策
• lab0（热身）不单独计分，但你绘制的控制流图、核心数据结构全景快照与时钟中断时序图会在 lab1 验收时被当场提问，请妥善保存在自己的工程目录中。
• 未按时验收或评定为 E 档怎么办：实验结束后一周内可申请一次集中补验，补验通过最高按 60 分（D 档）记入。与其被动拖延到补验，强烈建议每轮实验尽早着手实施，利用课间与课余时间提前验收。
